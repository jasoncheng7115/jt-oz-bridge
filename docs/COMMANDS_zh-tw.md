# 聊天指令

[English](COMMANDS.md)

在已連上的話題直接打字，就是送給 AI。指令都是 `!` 加一個英文字，前後不用加別的；用中文輸入法打的全形「！」也可以，手機鍵盤自動變成大寫（`!Status`）也沒關係。整則只有指令（和權限碼）時，結尾多打的「。」「!」「?」、`!` 後面的空格、全形英數字都不影響：`!stop。`、`! status`、`!ｏｋ　１２３４`。`!help` 會列出常用的指令，`!help stauts` 這種打錯的字也會說明你要的那個指令。

OpenCode 正在工作時，新訊息會送進進行中的回覆：OpenCode 在下一步就會讀到，就像在 Claude Code 工作時打字一樣。好幾則會依序一則一則送進去。當下插不進去時（OpenCode 在等權限、前面還有排隊的訊息，或送出那一刻會話剛好變動），訊息會等進行中的回覆完成，再開始自己的回覆，不會遺失。帶檔案的訊息、排程、被暫停過的訊息（`!stop` 後再 `!go`）一律會等著，自己開一個新的回覆。OpenCode 沒在工作時，訊息會立刻開始新的回覆。`!status` 看有哪些在等；`!stop` 停下進行中的回覆和等著的訊息。

請用有名稱的話題。Zulip 的「general chat」沒有話題名稱，Bridge 在那裡只會回一句提醒你換話題。一般訊息 Bridge 處理不了時，會回覆簡短原因並請你看 `!status`，不再默不作聲。

## Bridge 問你的事

| 指令 | 作用 |
| --- | --- |
| `!ok` | 答應 Bridge 剛問你的事：排程、切換 Agent、分出新對話、壓縮、回退、Git、OpenCode 重啟後重新連上（回一次 `!ok` 就好） |
| `!no` | 不要。把 Bridge 問你、還沒回答的事全部取消，也丟掉你還沒送出的訊息，什麼都不送 |
| `!ok 1234`／`!no 1234 原因` | 回覆 OpenCode 的權限要求，代碼在通知裡 |
| `!a 1234 答案` | 回答 AI 問你的問題 |
| `!1`、`!2`… | 選選單裡的項目；`!next` 下一頁 |
| `!pending` | 列出等你回覆的權限和問題 |

電腦版（桌面 app、網頁）在這些問題、暫停提示（`!go`／`!no`、`!ok` 重新接上）、`!stop` 之後的「繼續」和排程確認下面都有按鈕，按下去就等於打那個指令。手機 app 不顯示按鈕，照訊息裡的指令打就好。

## 控制

| 指令 | 作用 |
| --- | --- |
| `!stop` | 停下全部：中斷目前工作、暫停排隊的訊息、停止你在這裡的排程。停止後直接打新訊息就會繼續；`!go`／`!no` 只用在停止前還在排隊的訊息 |
| `!go` | 繼續：恢復暫停的佇列，送出還沒送出的訊息；新對話還在建立中時，就把它連上這個話題 |
| `!go new` | 只送新的：丟掉你一小時以前、還沒送出的舊訊息，其餘照順序送出。話題裡還留著一小時以前的舊訊息時，新訊息不會自動把舊的一起帶出去，而是先停下來讓你選 `!go new`／`!go`／`!no`（電腦版有按鈕） |
| `!status` | 目前狀態（回覆進行中時，會說是在等哪個工具，還是模型在思考或撰寫）和排隊中的訊息（依序編號並附開頭幾個字；還沒送出的會提示 `!go`／`!no`，電腦版有按鈕；等了一小時以上的會標出送出時間；有權限要求在等你時會寫出帶代碼的 `!ok`／`!no`，其他等你回覆的事指 `!pending`） |
| `!reconnect` | 通常用不到：OpenCode 重啟後，Bridge 會自己接回對話並用一行告知。沒能自動接回時，話題會用一行告知，直接回 `!ok` 就會接上（電腦版按按鈕也一樣）；`!reconnect` 是先看細節，再回 `!ok` 確認。期間送的訊息接上後會照順序送出，只有你自己停過的話題才要再打 `!go`；暫停提示和 `!status` 都會指出來 |

### Bridge 重新啟動時

Bridge 重新啟動不會讓話題停住。你最近 10 分鐘內傳的訊息，包括 Bridge 離線期間傳的，會在它回來後自動送出。如果有更早的訊息在等，就都不送，Bridge 回覆一次：`!go` 依序送出，`!no` 丟掉。離線期間傳的訊息若比較舊或被編輯過，不會送出；Bridge 會說一次，還需要的話請重新送。你自己選的暫停（`!stop`、`!oz queue pause` 或管理員暫停）會一直保留到有人恢復；這種本來就暫停的話題，離線期間傳的訊息也會收下，回你一次怎麼繼續（`!go`／`!no`），不會默不作聲。

無法照原樣送出的訊息（例如被編輯過或已無法確認）不會送出，Bridge 會說一次；它不會擋住後面的訊息。OpenCode 暫時連不上時，Bridge 會持續重試幾分鐘，仍不行才放棄那則訊息並告訴你。

## 對話

| 指令 | 作用 |
| --- | --- |
| `!go`、`!go 關鍵字` | 在還沒連上的話題選一個既有對話 |
| `!new` | 開新對話，選專案後可加標題 |
| `!disconnect` | 中斷這個話題的連線，對話本身留在 OpenCode |
| `!model` | 換模型 |
| `!agent` | 換 Agent |
| `!rename 標題` | 改對話標題 |
| `!fork` | 從這裡分出新對話，再回 `!ok` |
| `!compact` | 壓縮對話，再回 `!ok` |
| `!undo` | 回到某則訊息之前（先選訊息，再回 `!ok`） |
| `!redo` | 把回退的訊息帶回來 |
| `!discard` | 確定刪除回退的訊息 |
| `!archive`／`!unarchive` | 封存／取消封存 |

## 其他

| 指令 | 作用 |
| --- | --- |
| 「每半小時…到 18:00」 | 直接用一句話設排程，Bridge 回它的理解後，`!ok` 開始、`!send` 照原文只送一次、`!no` 不要 |
| `!schedule` | 列出這個話題的排程；停止用 `!stop` |
| `!commit 訊息`、`!push` | Git commit／push，先預覽，再回 `!ok`（需開啟） |
| `!send 文字` | 照原文送給 AI，文字以 `!` 開頭也一樣 |
| 不加 `!` 的 `ok`／`好`／`no` | 這裡有事在等你確認（確認、權限、重新接上）時，Bridge 會先問你是不是要 `!ok`／`!no`，不會把這個字送給 AI；要送給 AI 就回 `!send ok`。只有一個權限要求在等時，會直接寫出帶代碼的 `!ok 1234`／`!no 1234`，電腦版按鈕也帶代碼；有好幾件在等時，會請你用 `!pending` 看。如果在等的是 AI 問你的問題，會改請你用 `!pending` 看問題和回答方式。有事在等時單獨打 `1` 或 `2` 也一樣處理，當成用數字選第一個或第二個按鈕。沒有事在等時照常送給 AI |
| 打錯字的指令，例如 `!stauts` | 在已連線的話題，和常用指令只差一點（兩個字母對調；五個字母以上的指令另含少一個、多一個或錯一個字母）的字不會送給 AI。Bridge 會問你是不是要那個指令，例如 `!status`；電腦版按鈕可直接執行，或照原文送給 AI。也可以回 `!send !stauts` 照原文送出。其他以 `!` 開頭的文字照常送給 AI |
| `!steer -- 文字` | 和一般訊息一樣（也會送進進行中的回覆），文字照原文，並回一句說明送到哪裡 |
| `!lang zh-TW`／`!lang en`／`!lang auto` | 切換介面語言 |
| `!help`、`!help 指令`、`!help all` | 常用指令、單一指令用法、進階指令 |

## 進階指令

`!help all` 列出進階指令，例如 `!oz worktree`、`!oz checks`、`!oz recovery`、`!oz outputs`、`!oz git review`，以及選單按鈕送出的 `!oz <指令> <代碼>`。按鈕會自動送出，不用自己打。

每個一般指令背後都是一個進階指令，例如 `!go` 就是 `!oz queue resume`，`!undo` 就是 `!oz revert`。兩種寫法經過一樣的權限和來源檢查，紀錄也一樣。
