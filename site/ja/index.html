すべてオンプレミス：チャット・ブリッジ・エージェント・モデル

外出先でも、オンプレミスの AI エージェントに頼めます

jt-oz-bridge は、自前の Zulip のトピックを、自分のサーバー上の既存の OpenCode セッションにつなぎます。パソコンを開かなくても、VPN でターミナルに入らなくても、スマートフォンから作業を頼み、いま何をしているかを確認し、実行したいコマンドを承認して、返事を読めます。席に戻れば、同じセッションが OpenCode にそのまま残っています。

すべて自前、オンプレミスで

チャット、ブリッジ、エージェント、モデルはすべて自分の管理するマシンで動きます。ブリッジがやり取りするのは自分の Zulip と同じホストの OpenCode だけで、外部のクラウドサービスは使いません。

  1. スマートフォン／パソコンの Zulip外出中や当番中にそのまま質問
  2. 自前の Zulip組織で所有するチャット基盤
  3. jt-oz-bridge作業を渡し、進捗と結果を返す
  4. OpenCode エージェント元のセッションで作業を続け、使う MCP ツールを自分で選ぶ
  5. ローカルモデル＋MCPモデルもツールもサーバールームの中
  • データは外に出ないローカルモデルなら、質問・返事・ファイルは Zulip、ブリッジ、OpenCode、モデルの間だけでやり取りされます。
  • 記録もオンプレミス誰が何を頼み、何を承認したかの記録は、自分のホストに残ります。
  • 権限はそのままエージェントにできることは、引き続き OpenCode の権限とツール設定で決まります。
  • パソコン不要パソコンを開かず、VPN でターミナルに入らず、自前のチャットで聞くだけです。

開発プレビューです。ルーティング、保存、セキュリティチェックには大量の自動テストがあり、ブリッジは実際の OpenCode サーバーと Zulip 組織 1 つで毎日使われています。ほかの人による一連の利用や、公式の iOS／Android アプリでの動作はまだ検証していません。まずは捨ててもよいプロジェクトで試してください。

トピックでできること

普通の文章はセッションに送られます。コマンドは ! と英単語 1 つです。

作業を頼む

そのまま書きます。作業中に書き足すと、実行中のターンに加わるか、終わるのを待って送られます。

進み具合を見る

ツールの実行に合わせて、進捗メッセージ 1 件がその場で更新されます。数分かかっているときは、ツール待ちかモデル待ちかも知らせます。

権限リクエストに答える

!ok 4821 で今回だけ許可、!no 4821 で拒否します。パソコン版 Zulip には同じ選択肢のボタンも出ます。

ファイルを受け取る

!files でプロジェクト内を探し、!file パス で元のファイルを送ります。HTML はダウンロードのみで、表示はしません。

モデルやエージェントを変える

!model と !agent は OpenCode 自身が持つ選択肢を出します。既存のプロバイダーと MCP の設定はそのままです。

止める・続ける・やり直す

!stop でこのトピックの作業を止め、!go で続け、!new で登録済みプロジェクトに新しい会話を開きます。

!status で現在の状態、!help でほかのコマンドを確認できます。すべてのチャットコマンド（英語）

向いている場合、向いていない場合

向いている

  • チャット、エージェント、モデルをオンプレミスに置き、外部のクラウドサービスを通したくない。
  • OpenCode がすでに、自分で管理する Linux ホストでサーバーとして動いていて、ブリッジも同じホストに置ける。
  • 自分の Zulip サーバーがある、または立てるつもりがある。
  • プライベートチャンネルのメンバー全員が、その中の作業を見てよい（自分だけ、または少人数のチーム）。
  • 席でもスマートフォンでも、同じセッションを続けて使いたい。

向いていない

  • クラウドのサービスや、Slack・Teams・Telegram が必要。いま対応しているのは Zulip だけです。
  • ブリッジにエージェントを閉じ込めてほしい。ホスト上でエージェントが何をできるかは OpenCode 自身の権限で決まり、ブリッジが確かめるのは誰が頼めるかです。
  • 互いの作業を見てはいけない人どうしが、同じチャンネルを使うことになる。
  • サポート付きの正式版が必要。

仕組み

ブリッジは Bot アカウントで Zulip と、ループバックの API で OpenCode とやり取りします。OpenCode のデータベースを開くことも、OpenCode を再起動することもありません。

図は横にスクロールできます。

インストールされるもの

  • jt-oz-bridge serve：サービス本体。ループバックでのみ待ち受けます。
  • 専用の SQLite データベース。メッセージの内容はアプリケーションが暗号化して保存します。
  • OpenCode のアカウントで動く小さな読み取り専用の補助プログラム。どの OpenCode プロセスとプロジェクトディレクトリが本物かを確かめます。
  • 任意：jt-oz-bridge sessions と doctor 用の読み取り専用 observer、ブリッジの停止時と復帰時に Zulip へ知らせるユニット。

インストール・アップグレード・アンインストール

systemd のある Linux で、OpenCode と同じホストに専用の非 root ユーザーで動かします。各リリースは wheel の SHA-256 を名前にしたディレクトリに入り、依存パッケージはハッシュで固定され、CycloneDX SBOM が付きます。戻すときは前のディレクトリに切り替えるだけです。

インストール

  1. wheel、ハッシュ付きの requirements.txt、SBOM、またはオフラインバンドルを用意します。
  2. SHA256SUMS を確かめ、--require-hashes で新しい venv に入れます。
  3. 設定を書き、鍵を作り、migrate を実行し、ユニットを起動して /readyz を確認します。
  4. Zulip の Bot とプライベートチャンネルを用意し、OpenCode のプロジェクトを 1 つ登録します。
インストールガイド

アップグレード

  1. 新しいリリースを、動いているものの隣に入れます。
  2. ブリッジを止め、バックアップを取り、migrate を実行します。
  3. ユニットを新しいリリースに向け、/readyz を待ち、スモークチェックを行います。
  4. 戻すときは前のリリースに向け直します。スキーマが変わった後は、バックアップから復元します。
アップグレードガイド

アンインストール

  1. 必要なら最後のバックアップを取り、鍵はそれとは別に保管します。
  2. ユニット、リリース、状態、設定、サービスユーザーを削除します。
  3. Zulip と OpenCode のデータはそのまま残ります。Bot は Zulip で無効にしてください。

オフラインインストールの要点

# インターネットにつながるマシンで
uv build --wheel --out-dir "$OUT"
uv export --frozen --no-dev --no-emit-project --no-header --format requirements-txt -o "$OUT/requirements.txt"
pip download --require-hashes --only-binary=:all: --python-version 3.13 --platform manylinux_2_28_x86_64 \
  -r "$OUT/requirements.txt" -d "$OUT/wheels"      # SBOM と SHA256SUMS も添える

# ネットワークから隔離されたホストで
sha256sum -c SHA256SUMS
uv venv --offline --python "$PY" "$R/venv"
uv pip install --offline --no-index --find-links ./wheels --require-hashes -r requirements.txt --python "$R/venv/bin/python"
uv pip install --offline --no-index --no-deps jt_oz_bridge-*.whl --python "$R/venv/bin/python"

プラットフォームタグ、Python と uv の持ち込み、SBOM の確認を含む完全な手順はインストールガイドにあります。

セキュリティ

  • 設定したもの以外は許可しません。セッションに届くのは、登録した Zulip ユーザー、プライベートチャンネル、プロジェクトごとの許可だけです。Bot からのメッセージは無視し、モデルが書いた内容で権限が与えられることもありません。
  • 実行のたびに確かめ直します。送信者、チャンネルのメンバー、許可、結び付け、対象のセッションを毎回確認します。結果がわからない操作は自動で送り直さず、判断を待ちます。
  • エージェントにできることは OpenCode が決めます。OpenCode 自身のツール、MCP、システムの権限がそのまま効きます。チャットでの承認はサンドボックスではありません。
  • 秘密情報は所有者だけが読めるファイルに置きます。設定にはパスだけを書き、暗号鍵はバックアップと分けて保管します。
  • サービス自体も堅くしています。専用ユーザー、capability なし、厳しいファイルシステム保護、固定した依存パッケージ、リリースごとの SBOM。
