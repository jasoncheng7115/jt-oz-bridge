チャットから AI コーディングエージェントと対話する。

jt-oz-bridge は AI エージェントとメッセージングソフトをつなぐブリッジで、最初の対応は OpenCode × Zulip です。Zulip のトピックにタスクを書き込み、エージェントの作業を見守り、スマートフォンから権限リクエストに答え、完全な結果を受け取る。そのすべてを、デスクで使っているのと同じ OpenCode セッションの中で行えます。すべて自前のインフラで動作します。

GitHub のソース インストールガイド

ステータス

開発プレビュー 0.1.1。本番向けの完成版リリースではありません。

コアのルーティング、永続化、セキュリティ境界には大規模な自動テストがあり、フローの一部は実際の OpenCode サーバーと Zulip 組織で確認済みです。実際の利用者によるエンドツーエンドの利用と、公式 iOS／Android アプリでの利用はまだ検証されていません。まずは使い捨てのプロジェクトでお試しください。

できること

01

日常のチャットに AI エージェントを

タスク、進捗、質問、結果がチャットにまとまり、スマートフォンからもパソコンからも確認できます。

02

OpenCode × Zulip

OpenCode がエージェントとツールを実行し、Zulip がモバイル／デスクトップのチャット、プライベートチャンネル、トピックを提供します。

03

完全セルフホスト

メッセージング、ブリッジ、エージェント、モデルのすべてが自前のハードウェアで動き、データの流れを自分で管理できます。

04

コピーではなく同じセッション

各トピックは既存の OpenCode セッションに結び付きます。履歴のコピーも fork も、継続を装う別のバックエンドもありません。

05

スマートフォンから承認

権限リクエストやエージェントからの質問がトピックに届き、!ok 1234 かボタンで答えられます。

06

自分のモデルとツール

OpenCode 自身のカタログからプロバイダー、モデル、バリアントを選べ、既存の MCP 設定もそのまま使えます。

全体の構成

画面が狭い場合は、図を横にスクロールしてください。

コンポーネント

  • jt-oz-bridge serve：ブリッジ本体。Zulip のイベントを受け取り、認可を確認し、OpenCode API を呼び出して結果を届けます。待ち受けはループバックのみです。
  • 専用の SQLite データベース（PostgreSQL は開発中）。ペイロードはアプリケーション層で暗号化します。OpenCode のデータベースは一切開きません。
  • jt-oz-bridge sessions と doctor のための、任意の読み取り専用ローカルオブザーバー。
  • OpenCode のアカウントで動く小さな読み取り専用の補助サービス。どのプロセス、データセット、プロジェクトディレクトリが本物かを証明します。
  • ブリッジの停止時と復帰時に Zulip へ 1 回ずつ通知する任意のユニット。

1 トピック = 1 セッション

プライベートチャンネル「project-a」
├── ログイン修正 → OpenCode セッション A
└── API テスト   → OpenCode セッション B

トピックを作成し、使用を許可された既存のセッションを選ぶ（または登録済みプロジェクトで新しい会話を始める）だけで、あとは入力するだけです。チャンネルのメンバーは全員トピックを読めるため、閲覧者が異なる場合はプライベートチャンネルを分けてください。

主なコマンド

接続済みのトピックでは、通常のテキストは AI に送られます。コマンドはすべて ! と英単語 1 つです。

コマンド用途
!ok／!noブリッジの質問への はい／いいえ。!ok 1234 は権限リクエストへの回答
!stop／!goここでの作業をすべて停止／一時停止中の作業を続行
!status現在の状態とキュー内のメッセージ
!new／!disconnect新しい会話／トピックの接続を解除（セッションは OpenCode に残ります）
!model／!agentモデル／エージェントの切り替え
!files／!file パスファイルの検索／ダウンロード
!helpそのほかのすべて

インストール、アップグレード、アンインストール

ブリッジは Linux（systemd）上で、既存の OpenCode サーバーと並べて、専用の非 root ユーザーとして動作します。各リリースは wheel の SHA-256 を名前にした専用ディレクトリに置かれ、依存パッケージはハッシュで固定され、CycloneDX SBOM が付きます。

インストール

  1. wheel、ハッシュ付きの requirements.txt、SBOM を作成するか、依存 wheel を含むオフラインバンドルを持ち込みます。
  2. SHA256SUMS を検証し、--require-hashes で新しい venv にインストールし、SBOM を確認します。
  3. 設定、鍵の生成、migrate、systemd ユニットのインストール、/readyz の確認。
  4. Zulip の Bot とプライベートチャンネルを接続し、OpenCode のプロジェクトを 1 つ登録します。
インストールガイド →

アップグレード

  1. 新しいリリースを稼働中のものの隣にインストールします。
  2. ブリッジを停止し、バックアップを取り、migrate します。
  3. drop-in を切り替え、/readyz を待ち、スモークチェックを行います。
  4. ロールバックは前のリリースに向け直すだけ。スキーマ変更後は前に進めて修正するか、バックアップを復元します。
アップグレードガイド →

アンインストール

  1. 必要なら最後のバックアップを取り、鍵は別に保管します。
  2. ユニット、リリース、状態、設定、サービスユーザーを停止して削除します。
  3. Zulip と OpenCode のデータは残ります。Bot は自分で無効化してください。

オフラインインストールの要点

# connected machine
uv build --wheel --out-dir "$OUT"
uv export --frozen --no-dev --no-emit-project --no-header --format requirements-txt -o "$OUT/requirements.txt"
pip download --require-hashes --only-binary=:all: --python-version 3.13 --platform manylinux_2_28_x86_64 \
  -r "$OUT/requirements.txt" -d "$OUT/wheels"      # plus SBOM and SHA256SUMS

# air-gapped target
sha256sum -c SHA256SUMS
uv venv --offline --python "$PY" "$R/venv"
uv pip install --offline --no-index --find-links ./wheels --require-hashes -r requirements.txt --python "$R/venv/bin/python"
uv pip install --offline --no-index --no-deps jt_oz_bridge-*.whl --python "$R/venv/bin/python"

正確なプラットフォームタグ、Python と uv の持ち込み、SBOM の確認を含む完全なコマンドはガイドにあります。

セキュリティモデル

  • 既定は拒否。セッションに触れられるのは、設定済みの Zulip ユーザー、プライベートチャンネル、プロジェクト単位の付与だけです。Bot のメッセージは無視され、モデルの出力が権限を与えることはできません。
  • 実行の直前に再確認。送信元メッセージ、メンバー、付与、バインド、対象のセッションを改めて確認し、結果が不明な操作は保留して、むやみに再送しません。
  • OpenCode が正であり、非公開のまま。使うのはループバックの API だけで、データベースは読まず、再起動もしません。エージェントに何ができるかは OpenCode 自身のツール、MCP、OS の権限で決まり、ブリッジの確認はサンドボックスではありません。
  • シークレットは参照で、所有者だけが読めるファイルを指します。暗号鍵はバックアップと分けて保管します。
  • ファイルはファイルとして。元のバイト列だけを返し、HTML はダウンロードとしてのみ提供します。インタラクティブなプレビューはありません。
  • 堅牢化されたサービスとサプライチェーン。専用ユーザー、capability なし、厳格なファイルシステム保護、ハッシュ固定の依存パッケージ、リリースごとの SBOM。
